## 1. Коротке резюме та головний висновок

Проєкт пройшов еволюцію від статичного GUI з вигаданими формулами до **повноцінної розподіленої аналітичної платформи**:
1. **На клієнті (Desktop):** Зручний, масштабований інтерфейс на Avalonia UI 11 з живою статистикою гравців, розбором ігрових таймлайнів (Tactical Breakdown), конструктором драфтів 5v5 та системою оцінки шансів на перемогу.
2. **На сервері (VPS Ubuntu 24.04):** Працює автономний фоновий демон `systemd` (`gameanalytics-trainer.service`), який безперервно збирає виключно рейтингові ігри Summoner's Rift (Queue 420), витягує метрики перших 15 хвилин матчу (золото, вбивства, крипи, досвід, Личинки Безодні, Герольд) та тренує градієнтний бустинг `FastTree` у ML.NET.

## 2. Що вже реалізовано (Status Quo)

### 2.1. Вкладка «Аналітика гравця» (`PlayerAnalyticsView`)
* **Пошук за Riot ID:** Підтримка нового формату Riot ID (`GameName#TagLine`) через Riot Account-V1 + Summoner-V4.
* **Підтримка регіонів:** 11 платформних серверів (EUW, EUNE, NA, KR, TR, RU тощо) з коректною маршрутизацією на регіональні хаби (europe, americas, asia, sea).
* **Картки матчів:**
  * Візуалізація результату (Victory/Defeat), KDA, CS/min, золота та предметів.
  * Інтерактивні підказки (Tooltips) для предметів із реальними даними DataDragon (вартість, стаки, опис пасивок) та вбудованим кешем/фолбеками.
  * Оцінка матчу: грейди (MVP, ACE, S/A/B/C/D) на базі внеску гравця в команду.
  * **Вкладка тактичного розбору (Tactical Breakdown):** Похвилинні події (перша кров, забиті дракони, вежі, личинки безодні із групуванням `x3`), а також Gap Analysis (порівняння показників гравця з еталонами його рангу від Iron до Challenger).
* **Нормалізація чемпіонів:** Коректна обробка DataDragon ID (Wukong -> MonkeyKing, Renata Glasc -> Renata, Kai'Sa -> Kaisa, Nunu -> Nunu & Willump).
* **Масштабування інтерфейсу (UI Zoom):** Підтримка масштабів 100%, 115% та 125% без з'їзду верстки для будь-яких моніторів.

### 2.2. Вкладка «Аналіз драфту та ML Предикшн» (`DraftPredictionView`)
* **5v5 Драфт-арена:** Вибір по 5 чемпіонів для Синьої та Червоної команд (Top, Jungle, Mid, Bot, Support) з фільтрацією за класами та пошуком.
* **Калькулятор синергії:** Автоматичний перерахунок середнього вінрейту піків команд на основі свіжої бази DataDragon.
* **Аналіз скейлінгу композицій (Power Spike Curves):** Оцінка сили піків обох команд за фазами (Early 0-15m, Mid 15-25m, Late 25m+) з визначенням він-кондишн (Early Aggro / Mid Spike / Late Hyper-Scale).
* **Симуляція 15-ї хвилини:** Повзунки й селектори ключових факторів ранньої гри (First Blood, First Tower, First Dragon, різниця золота, вбивств, веж, драконів, личинок безодні Voidgrubs, герольдів, різниці CS та XP).
* **Врахування драконячих душ (Dragon Souls):** Моделювання впливу 6 типів душ (Infernal, Mountain, Ocean, Cloud, Hextech, Chemtech) на шанси камбеку або закріплення перемоги.
* **Live LoL Client Integration (порт 2999):** Моніторинг локального клієнта LoL у реальному часі та зчитування стану гри одним кліком.
* **ML-рушій прогнозування:** Використання бібліотеки `Microsoft.ML` (ML.NET).
* **Бенчмарк алгоритмів:** Порівняння 3-х класифікаторів (`FastTree`, `FastForest`, `SdcaLogisticRegression`) за метриками Accuracy, AUC-ROC, F1-Score та часом навчання.
* **Кнопка локального перенавчання:** Можливість тренувати модель на збережених локальних матчах безпосередньо з інтерфейсу.

### 2.2.1. Вкладка «Аналітика гравця» (`PlayerAnalyticsView`)
* **Похвилинний тактичний розбір гри (Tactical Breakdown):** Оцінка матчу, грейди (MVP, ACE, S, A...), аналіз помилок проти стандарту рангу (Gap Analysis).
* **Експорт тренерського звіту (Coach Report Export):** Експорт структурованого звіту розбору гри у буфер обміну (Markdown) або збереження у файл (`reports/coach_report_*.md`).

### 2.3. Вкладка «Історія матчів» (`MatchHistoryView`)
* Повноцінний SQLite кеш через **Entity Framework Core 9**.
* Перегляд збережених у базі матчів офлайн без звернення до API Riot.
* Можливість очищення локального кешу однією кнопкою.

### 2.4. Вкладка «Налаштування» (`SettingsView`)
* Введення Riot Games API ключа та збереження конфігурації у `appsettings.json` / `appsettings.local.json`.
* Перевірка з'єднання з Riot API («Тест з'єднання»).
* Налаштування автономного Mock/Demo режиму для перевірки програми без активного ключа або за відсутності інтернету.
* Статистика середовища (.NET версія, ОС, шлях до бази SQLite, інформація про підключений VPS сервер).

### 2.5. Надійність та Riot API compliance
* **RiotRateLimiter:** Реалізація Sliding-Window Token Bucket, розділена за регіонами (20 запитів/сек, 100 запитів/2 хв).
* **Обробка HTTP 429 (Too Many Requests):** Автоматичний парсинг заголовка `Retry-After` із паузою та джитер-бек-оффом.
* Жодного доступу до оперативної пам'яті гри чи Vanguard — повна відповідність правилам Riot Games.

## 3. VPS Daemon & ML.NET: У чому реальний профіт?

### Чому раніше результати предикшну були суб'єктивними:
Раніше за замовчуванням модель ініціалізувалася на синтетичних (штучно згенерованих) даних. Вона базувалася на закладених правилах: «якщо перевес 1500 золота, дати +20% до шансу перемоги». Тобто модель фактично повторювала наші власні припущення, а не реальні закономірності гри.

### Що ми маємо зараз завдяки VPS:
1. **Збір реальних високорангових ігор (Ranked Solo/Duo, Queue 420):**
   * VPS автономно обходить граф гравців (починаючи з seed PUUID `Qu4dyz#qu4`).
   * Для кожного матчу викачується повний таймлайн (`MATCH-V5 Timeline`) із фіксацією стану на 15-й хвилині:
     * `GoldAt15` (золото команд)
     * `KillsAt15` (вбивства)
     * `CsAt15` (фарм міньйонів та нейтральних монстрів)
     * `XpAt15` (досвід команд)
     * `VoidgrubKills` (кількість хробаків безодні)
     * `RiftHeraldKills` / `FirstRiftHerald` (Герольд безодні)
     * `FirstBlood`, `FirstTower`, `FirstDragon`
2. **Навчання справжньої моделі FastTree (LightGBM/Boosted Trees):**
   * Алгоритм знаходить нелінійні взаємозв'язки. Наприклад: як взяття трьох личинок бездні компенсує відставання у 800 золота? Що сильніше корелює з перемогою: перевага по XP чи перевага по фрагах?
   * За результатами 22+ епох на 440+ матчах модель показала:
     * **Точність (Accuracy): ~95.3%**
     * **AUC-ROC: 0.994**
     * **F1-Score: 0.955**
3. **Готові ваги моделі:**
   * Сервер експортує бінарний файл `fasttree_model.zip`, який можна підставити в додаток, і клієнт прогнозуватиме гру на реальному інтелекті без жодних розрахунків на сервері під час матчу (inference займає < 2 мс).

## 5. Архітектура рішення (Multiplatform Architecture)

Проєкт побудований за принципами **Clean Architecture**:

```
multiplatform/
├── src/
│   ├── GameAnalytics.Core/           # Чиста доменна логіка: ентіті Match, Participant, TeamStats, інтерфейси
│   ├── GameAnalytics.Infrastructure/ # Робота з даними: EF Core 9 SQLite, RiotApiClient (HTTP + RateLimit), DataDragon
│   ├── GameAnalytics.ML/             # ML.NET алгоритми (FastTree/FastForest/SDCA), VpsTrainingWorker, датасет-колектор
│   └── GameAnalytics.Desktop/        # Presentation Layer: Avalonia UI 11, MVVM (CommunityToolkit), XAML Views
├── tests/
│   └── GameAnalytics.Tests/          # 56 юніт-тестів (xUnit) для DataLayer, ML-пайплайнів та ViewModels
├── .github/workflows/
│   └── build-and-test.yml            # Кросплатформний CI пайплайн (Ubuntu Linux + Windows)
└── README.md
```

## 6. Детальний Roadmap: Що можна зробити в майбутньому

Ось структурований список перспективних ідей, які можна додати в проєкт:

### 🌟 Напрямок 1: Автоматична синхронізація Клієнт ↔ VPS (Cloud Sync)
* **API-ендпоінт або пряме завантаження моделі в один клік:**
  Додати в налаштування додатка кнопку: *«Оновити ML-модель з хмари»*. Клієнт сам звертається по HTTP/HTTPS або SFTP до VPS і завантажує найсвіжіший `fasttree_model.zip`.
* **Автоматична щотижнева синхронізація:** При старті програми раз на кілька днів непомітно у фоні звіряти хеш або дату моделі та підтягувати свіжу.

### 🌟 Напрямок 2: Розширення факторів для ML-моделі
* **Врахування драконячих душ (Dragon Souls):** Додати в фічі тип взятого дракона (Хімічний, Гекстековий, Морський тощо).
* **Врахування піків конкретних чемпіонів та контр-піків:** Зараз модель враховує середній вінрейт піків команди. Можна додати матрицю матчапів (Top vs Top winrate, Mid vs Mid).
* **Оцінка скейлінгу композицій (Early game vs Late game comp):** Додати розрахунок темпу драфту: піки ранньої гри (Renekton, Elise, Draven) проти піків пізньої гри (Kayle, Kassadin, Smolder).

### 🌟 Напрямок 3: Реальний час / Live Game Overlay (за бажанням)
* Опитування локального клієнтського порту League of Legends Client API (`https://127.0.0.1:2999/liveclientdata/allgamedata`) під час реального матчу (дозволено політикою Riot для персонального відображення).
* Предикшн шансу на перемогу прямо на 15-й хвилині твого реального матчу в реальному часі.

### 🌟 Напрямок 4: Експорт звітів та аналітика
* Генерація красивого PDF-звіту або зображення інфографіки після матчу («Розбір гри для тренера»).
* Додавання графіків приросту золота по хвилинах (Line Chart на базі ScottPlot або LiveCharts2).

### 🌟 Напрямок 5: CI/CD та дистрибуція
* Налаштувати GitHub Release action, який при створенні git-тегу автоматично компілює `GameAnalytics-win-x64.zip` та `GameAnalytics-linux-x64.tar.gz`.
